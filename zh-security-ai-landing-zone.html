第 02 章 · Slide 5 · FTE Offer 4–6 周转型冲刺 (Transformation Sprint)

FTE Offer 4–6 周转型冲刺：为什么第 3 周（`Secure AI Landing Zone`）决定项目成败

核心铁律：没有第 3 周完成 ② Secure AI Landing Zone 与 ③ Copilot as the UI for AI，第 4–5 周开发的 3 个业务 Agent 将无法通过安全合规审批进入生产环境。

第 1–2 周 · Gate 1
① AI Discovery to Commitment

梳理 5–10 个可量化业务成果并锁定高管赞助人；第 2 周末通过 Gate 1 锁定优先落地的 Agent 场景。

第 3 周 · 生产上线强制前提
② Secure AI Landing Zone + ③ Copilot 统一入口

部署 Entra Agent ID + 条件访问、Purview 标签/DLP/DSPM、Agent 365 注册表、Defender 运行时防护接入 SOC，并将 Copilot 设为统一入口。

第 4–5 周 · 敏捷构建
④ 构建并上线 3 个生产级 Agent

在第 3 周着陆区基线之上完成 3 个业务 Agent 的构建、验证与投产，确保每个 Agent “出生即受控”。

第 6 周 · Gate 2
⑤ Frontier Transformation Roadmap

输出跨季度 Frontier AI 演进路线图；第 6 周末通过 Gate 2（3 个 Agent 投产 + 路线图定稿）并移交持续运营。

03 · Security for AI — Copilot 统一入口 × Microsoft Agent 365 (Slides 6–23)

安全 AI 着陆区五大支柱（“Born Governed / 出生即受控”）交互解构

交互式浏览体验层（`Copilot as the UI for AI`）、控制平面（`Microsoft Agent 365` 五大支柱）、终端延伸（`Defender + Intune`）与 `M365 E7 (Frontier Suite)` 许可体系。

Slides 6, 8, 22–23 体验层与 M365 E7 许可底座

Copilot 作为 AI 统一入口 + M365 E7 (`Frontier Suite`)

没有统一入口，每个业务部门自建的 AI 工具都会变成独立登录、数据孤立、无法审计的影子 AI。Copilot as the UI for AI 统一员工交互入口，而 M365 E7 提供完整安全底座。

体验层：Copilot as the UI for AI (Slides 6 & 8) 统一交互入口

统一承载 Copilot Chat、Researcher、Copilot Cowork 与 Agents in Copilot & Teams，向下连接微软原生 Agent、Copilot Studio / Foundry 自建 Agent 及第三方 Agent，统一访问 M365 数据、业务系统 (LOB) 与 MCP/API。

Microsoft 365 E7 (`Frontier Suite`) 套件构成 (Slide 22) 一站式 Frontier 底座

M365 E7 = Microsoft 365 E5（Defender + Purview + Intune）+ Microsoft Agent 365（Agent 统一控制平面）+ Microsoft Entra Suite（零信任身份）+ Microsoft 365 Copilot + Work IQ。

Microsoft Agent 365 单独购买先决条件 (Slide 23) 4 类合格基础订阅

客户单独增购 Microsoft Agent 365 需持有以下任一基础许可：
1. M365 E5 / A5 / Business Premium · 2. Defender Suite + Purview Suite · 3. Defender Suite Edu + Purview Suite Edu · 4. Defender and Purview Suite FLW。

Project Perception：红/蓝/绿三智能体闭环

在统一安全与暴露面图谱 (Unified Security & Exposure Graph) 之上运行的多智能体、多模型协同引擎（关联 DeviceProcessEvents、SignInLogs、AlertEvidence、ExposureGraphNodes、RedTeamOperations 等 19+ 核心表）：

  • 🔴 Red Team Agent（红队智能体 · 模拟攻击）：模拟真实攻击、绘制攻击路径、发现关键扼制点 (Chokepoints)、扫描脆弱代码、暴露检测盲区。
  • 🔵 Blue Team Agent（蓝队智能体 · 检测与分类）：实战化威胁情报、自动重构攻击时间线、分诊高优告警、剔除误报噪音。
  • 🟢 Green Team Agent（绿队智能体 · 修复与补救）：弥合防御覆盖缺口、分析安全态势、验证真实暴露面、按根因优先级推进修复。
Slide 27 Private Preview 预览

MDASH：100+ 专项 AI 智能体协同

传统代码扫描工具产生海量误报，耗费研发与安全团队精力。MDASH 编排 100+ 专项 AI 智能体，融合前沿大模型 (Frontier Models) + 微软专有安全模型：

  • 阶段 1 · 深度漏洞挖掘：跨源码与依赖树进行多智能体深度语义分析。
  • 阶段 2 · 自动化可达性验证：在隔离沙箱中验证漏洞触发前提与调用链。
  • 阶段 3 · 可利用性证明 (Exploitability Proof)：端到端证实漏洞真实可被利用，并与 Microsoft Defender 深度集成。
Slides 28–32 aka.ms/ISOCDefender

ISOC in Microsoft Defender 演进路线

面向符合条件的 Defender Suite、M365 E5 与 M365 E7 客户，在 Defender 门户内原生提供内置 SIEM 与智能 SOC 能力：

  • 今日已可用 (Slide 32)：内置 SIEM（第一方 + 第三方数据关联）、Case Management 案件管理 (aka.ms/caseindefender ↗)、SOAR 剧本生成器、Workbooks 与 UEBA。
  • 2026年11月重磅上线 (Slide 32)：90 天数据留存 (90-Day Data Retention)、Content Hub + CI/CD、威胁情报平台、SOC 优化以及 Project Perception 正式版 (GA)。
