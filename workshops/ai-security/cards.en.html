MY TAKE

Blueprint for production AI Security vs common anti-patterns

✅ Good fit
  • Enforcing M365 DEFEND 5-Tier exit gates & Purview Tier 3 Data Control (DSPM for AI + Copilot DLP) before enterprise AI rollout
  • Testing multi-agent topologies against propagation, amplification, trust capture, and proxy chains with deterministic server-side judges
  • Isolating untrusted agent code execution inside Kata VMs / E2B Firecracker MicroVMs with IMDS blocked and Tetragon eBPF active
  • Binding every agent action to dual Entra Agent ID attribution (`Blueprint + Human Sponsor`), PDP/PEP gates, and `C_accepted(g)`
  • Sanitizing open-web grounding via Microsoft Web IQ and locking autonomous transactions with AP2 `MandateVC` + FIDO2 Passkeys
⛔ Not for
  • Treating system prompts, `SKILL.md` text, or `--yolo` CLI flags on a developer's host OS as an enterprise security boundary
  • Using a single-turn LLM-as-Judge to evaluate multi-agent red-team survival when the judge itself is vulnerable to injection
  • Running multi-tenant code-interpreter agents in shared-kernel containers with access to cloud IMDS (`169.254.169.254`)
  • Deploying open-source OCR/vision weights (`CC BY-NC 4.0`) inside commercial SaaS without automated license compliance gates
