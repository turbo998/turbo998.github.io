def verify_defend_progression(current_tier, target_tier, passed_gates, risk_register_signed):
    required = EXIT_GATES[target_tier]  # Base:11, Sec:12, Comp:11, Complete:8, Extend:9
    if target_tier == "DEFENDExtend" and current_tier != "DEFENDComplete":
        return "<answer>BLOCKED: DEFENDExtend requires DEFENDComplete controls in place (Slide 40)</answer>"
    missing = required - passed_gates
    if missing and not risk_register_signed:
        return f"<answer>HOLD_AT_{current_tier}: {len(missing)} mandatory exit criteria unmet</answer>"
    if target_tier in ("DEFENDCompliance", "DEFENDComplete"):
        enable_purview_tier3(["Copilot_DLP", "DSPM_for_AI", "Insider_Risk_Adaptive_Protection"])
    return f"<answer>APPROVED_{target_tier}: Low-Level Design (LLD) + Change Control Baseline Locked</answer>"

MY TAKE

Where the DEFEND Partner Playbook excels, and what to pair it with

✅ Good fit
  • SMB & mid-market MSPs building repeatable, high-margin managed security & compliance practices on M365 Business Premium
  • Pre-Copilot data governance readiness using the 4-Tier Purview-as-a-Service blueprint (Protect → Govern → Control → Assure)
  • Enforcing strict operational discipline via Low-Level Designs (LLDs), Risk Registers, Change Control, and 51 exit gates
  • Scaling multi-tenant baseline management via Microsoft 365 Lighthouse (GDAP) and Intune Plan 1 compliance policies
  • Bridging security operations (Defender XDR) and insider/AI data risk (Purview Adaptive Protection) before Sentinel SIEM
⛔ Not for
  • Treating DEFEND as an official Microsoft licensing SKU rather than a partner-authored managed service blueprint
  • Protecting Azure IaaS/PaaS VMs, AKS clusters, or MicroVM sandboxes without adding Microsoft Defender for Cloud
  • Jumping straight from DEFENDBase to DEFENDExtend (Sentinel) without completing DEFENDComplete XDR + Purview controls
  • Runtime kernel-level sandboxing of autonomous code-execution agents (pair with Track 03 Kata/Firecracker + Track 02 Red-Team Lab)
