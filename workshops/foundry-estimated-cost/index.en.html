Key Finding A: Why Diagnostic Settings AzureMetrics Export Must Be Avoided

Many platform teams route AllMetrics via Diagnostic Settings into Log Analytics and query the AzureMetrics table. For FoundryModelEstimatedCost, live testing exposed two severe failures:

  • Unsupported Export Contract (DS Export: No): Exporting into AzureMetrics strips model and deployment dimensions needed for multi-tenant showback.
  • Up to 95.1% High-Concurrency Point Loss: Under burst concurrency, AzureMetrics dropped up to 95.1% of points, whereas direct Microsoft.Insights/metrics REST queries captured $0.69022000 with 0.0000% variance.

Key Finding B: Multi-Project & Agent Cost Attribution Strategy

On both Account-level and Foundry Project-level /openai/v1 inference endpoints, the ProjectId dimension on FoundryModelEstimatedCost currently emits 'N/A'.

  • For direct /openai/v1 workloads: Provision dedicated ModelDeploymentName per business unit or tenant during Preview for deterministic 100% attribution.
  • For Foundry Agent Service workloads: Query the sibling metric AgentModelEstimatedCost on Microsoft.CognitiveServices/accounts/projects, which natively exposes AgentName and AgentVersion dimensions.

✓ Good Fit (Recommended for Immediate Partner Rollout)

  • Sub-5-Minute Runaway Agent Circuit-Breakers: Configure PT5M Microsoft.Insights/metricAlerts to catch runaway retry loops within 2 minutes instead of waiting 12–24 hours for Cost Management exports.
  • Cache-Heavy RAG & Multi-Turn Agents: Automatically incorporates 75%–90% prompt-cache discounts where naive token KQL inflates spend by 40%–70%.
  • Unified 1P + 3P Model Showback: Covers GPT-5.4 / GPT-4.1, 3P partner models (e.g., MoonshotAI/Kimi-K2.6), and DataZoneStandard deployments via one REST contract.

✕ Not For (Do Not Position as Invoice Replacement)

  • Customer Monthly Invoicing: Reflects public retail PayGo list rates only; excludes negotiated enterprise EA, MCA, and MACC discounts.
  • Embedding-Only or Image-Generation Pipelines: Emits $0 for text-embedding-3-large, FLUX.2-pro, FLUX.2-flex, and gpt-image-* in Preview.
  • PTU Reservations & Full-Stack RAG Spend: Excludes Provisioned Throughput hours, fine-tuning training/hosting hours, and downstream Azure AI Search / Cosmos DB bills.

Production Recipe 1: Split REST / CLI Queries (Avoid the ProjectId eq '*' HTTP 400 Trap)

API Batching Gotcha: Never batch FoundryModelEstimatedCost,InputTokens,OutputTokens in a single query when passing $filter="ProjectId eq '*'"! Because InputTokens and OutputTokens do not define a ProjectId dimension, the API fails the entire request with HTTP 400 BadRequest. Query FoundryModelEstimatedCost separately as shown below.
Sanitized Two-Call Azure CLI Telemetry Pattern 
# 1) Query FoundryModelEstimatedCost independently on the account scope
az monitor metrics list \
  --resource "/subscriptions/<sub-id>/resourceGroups/<rg-name>/providers/Microsoft.CognitiveServices/accounts/<foundry-account>" \
  --metric "FoundryModelEstimatedCost" \
  --interval PT5M \
  --aggregation Total \
  --filter "ModelDeploymentName eq '*' and ModelName eq '*'"

# 2) For Foundry Agent Service workloads, query AgentModelEstimatedCost on the project sub-resource
az monitor metrics list \
  --resource "/subscriptions/<sub-id>/resourceGroups/<rg-name>/providers/Microsoft.CognitiveServices/accounts/<foundry-account>/projects/<project-name>" \
  --metric "AgentModelEstimatedCost" \
  --interval PT5M \
  --aggregation Total \
  --filter "AgentName eq '*' and AgentVersion eq '*'"

Production Recipe 2: Near-Real-Time PT5M Spend-Spike Alert (Bicep)

Microsoft.Insights/metricAlerts — 5-Minute USD Burst Threshold Guardrail 
param foundryAccountId string
param actionGroupId string
param fiveMinUsdThreshold int = 25 // Trigger alert when any deployment exceeds $25 in 5 minutes

resource foundrySpendBurstAlert 'Microsoft.Insights/metricAlerts@2018-03-01' = {
  name: 'alert-foundry-estimated-cost-pt5m'
  location: 'global'
  properties: {
    description: 'Near-real-time USD burst circuit-breaker for Microsoft Foundry & Azure OpenAI deployments'
    severity: 2
    enabled: true
    scopes: [foundryAccountId]
    evaluationFrequency: 'PT1M'
    windowSize: 'PT5M'
    criteria: {
      'odata.type': 'Microsoft.Azure.Monitor.SingleResourceMultipleMetricCriteria'
      allOf: [
        {
          name: 'EstimatedUsdBurst'
          metricNamespace: 'Microsoft.CognitiveServices/accounts'
          metricName: 'FoundryModelEstimatedCost'
          operator: 'GreaterThan'
          threshold: fiveMinUsdThreshold
          timeAggregation: 'Total'
          dimensions: [
            {
              name: 'ModelDeploymentName'
              operator: 'Include'
              values: ['*']
            }
          ]
        }
      ]
    }
    actions: [
      {
        actionGroupId: actionGroupId
      }
    ]
  }
}

Partner FinOps FAQ & Reference Repository

Q1: Does enabling or reading FoundryModelEstimatedCost incur extra Azure Monitor charges?

Within standard platform quotas, the metric itself is completely free ($0). It is emitted automatically as a standard Azure Monitor platform metric on Microsoft.CognitiveServices/accounts with 93-day retention; standard Azure Monitor pricing applies only if you provision metric alert rules or high-frequency custom API polling beyond free tiers.

Q2: Does this work on existing standalone Azure OpenAI resources (kind=OpenAI), or only new Foundry (kind=AIServices) accounts?

Both work out of the box. Live verification on 2026-11-23 confirmed FoundryModelEstimatedCost is registered on both kind: AIServices (Microsoft Foundry) and standalone kind: OpenAI accounts without resource migration.
