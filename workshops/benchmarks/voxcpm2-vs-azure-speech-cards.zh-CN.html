4 / 7 · UNDER THE HOOD · 源码协议与确定性频谱验证器

内置 FSQ(dim=512, s=9) 半离散锚点 + 非对称 3× 超分声码器契约

上方为 OpenBMB/VoxCPM 核心前向与流式限制源码契约，下方为纯 Python 1024 点 Welch FFT 确定性验证输出。

# src/voxcpm/model/voxcpm2.py (lines 258, 345, 667) & audiovae_v2.py
ref_wave_16k = torchaudio.functional.resample(ref_wav, orig_sr, 16000)
z_25hz       = audio_vae_v2.encode(ref_wave_16k)          # hop=640 -> 25 Hz, dim=64
patches      = patchify(z_25hz, patch_size=4)             # 6.25 Hz (160 ms / step)
seq_input    = concat([103, loc_enc(ref_patches), 104], text_tokens)

h_tslm       = base_lm_28L(seq_input)
h_fsq        = torch.round(torch.tanh(proj(h_tslm)) * 9) / 9  # Internal FSQ(512, s=9)
h_ralm       = residual_lm_8L(h_fsq + loc_enc_unquantized_bypass)
pred_patch   = loc_dit.sample_cfm(h_ralm, steps=10, cfg_value=2.0)
pcm_48k      = streaming_vae_decoder.decode(pred_patch)   # strides [8,6,5,2,2,2]=1920 -> 48 kHz
if streaming: retry_badcase = False                       # Anti-babble retry disabled in stream!

7 / 7 · MY TAKE · 架构师适用边界与投产就绪度

月产超 2,500 万字符创意克隆首选 VoxCPM2；金融合规与口型同步坚守 Azure

企业生产环境推荐采用“前置策略路由 + 双轨语音引擎 + 强制隐形水印”参考架构。

PASSGood fit · 推荐采用 VoxCPM2 场景
  • 高表现力播客、有声书与游戏 NPC 配音：48kHz 原生超分 (17.7 kHz BW) 自然保留耳语、哭腔、笑声与跨方言韵律。
  • 数据不出域私有声音资产克隆：Apache-2.0 宽松商用许可，5–10 分钟语料即可完成 LoRA 专属声线微调。
  • 东南亚多语种出海本地化：缅甸语 (1.42%)、老挝语 (1.90%)、柬埔寨语 (2.05%) 可懂度显著优于同级开源模型。
  • 月产 >2,500 万字符稳态降本：单卡 vLLM-Omni 较 Azure HD 降低 60%–85% 成本（8.5 亿字符/月规模可由 ~$12.8k/月降至 ~$3.2k/月）。
BOUNDARYNot for · 应选用 Azure Speech 等场景
  • 金融/医疗/政务强合规交易播报：无 SSML / 与热更新词典，生僻字绕口令 CER 达 8.13%，须用 Azure Speech。
  • 3D 数字人实时口型同步与影视卡帧译制：输出严格量化在 N × 160ms 且无 Viseme 流，应选用 Azure 0.1ms Viseme 或 IndexTTS-2。
  • 超低延迟 (<90ms) 全双工电话语音打断：首包受 160ms Patch 限制 (~135ms)，低于 90ms 预算宜选 Cartesia Sonic 3.6。
  • 无外挂防伪治理的对外开放克隆接口：开放权重无内置水印与活体声纹门禁，上线必须串联活体校验与 AudioSeal + C2PA 水印。
