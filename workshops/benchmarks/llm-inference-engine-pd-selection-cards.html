2 / 7SCENARIO: MIXED 32K RAG + STREAMING CHAT & 16K MULTI-TURN AGENT SERVING

Isolating Prefill From Decode Over 400G RDMA Keeps P99 TPOT at 18.2 ms (`3.76x` Lower) and Lifts Per-GPU SLA Goodput 2.38x

Input Case (`Llama-3-70B FP8 on 8×H200` · `32K Long-Prompt RAG + Interactive Chat` · `SLA: P99 TPOT < 30 ms`)

In a standard co-located deployment, a 32K-token RAG prompt saturates GPU Tensor Cores (`512.0 FLOP/B`). Even with Chunked Prefill (`chunk=2048`), co-scheduled streaming decode requests suffer 68.4 ms P99 TPOT (`2.28x` above the `30 ms` SLA), forcing architects to throttle concurrency to `680 tok/s/GPU`.

Decision 1 · Dynamo + Mooncake 400G RDMA PD Disaggregation choice · Act automatically

Separate the fleet into dedicated Prefill Workers and Decode Workers connected via Mooncake Transfer Engine (`GPUDirect RDMA` / `libfabric FI_HMEM` `#4427`). Transferring incremental KV blocks over 400G RoCEv2 takes 22.8 ms without consuming Decode SMs, keeping Decode P99 TPOT flat at 18.2 ms (3.76x lower) and raising SLA-compliant goodput to 1,618.4 tok/s/GPU (2.38x).

Decision 2 · SGLang RadixAttention + Deferred Page Reuse (`#48852`) & vLLM Batch Encoder Graphs (`#65227`) score · Act automatically

For 16K multi-turn agent workflows with 75% shared prefix (`12K` cached tokens), SGLang RadixAttention + deferred unified page reuse drops TTFT from 186.4 ms to 54.0 ms (3.45x speedup, 2.85x QPS), while vLLM single-replay batch encoder CUDA graphs cut multimodal launch overhead 3.20x (`11.2 -> 3.5 ms`).

Heterogeneous Right-Sizing Bonus: Pairing compute-dense Prefill GPUs with memory-bandwidth-rich Decode GPUs reduces cost per 1M SLA-compliant tokens from $0.76 to $0.50 (-34.2%).

7 / 7MY TAKE · ARCHITECT SELECTION PLAYBOOK & READINESS

When to Choose vLLM, SGLang, TensorRT-LLM, or PD Disaggregation in Production

✅ Good Fit (When to Adopt Each Stack)

• Choose vLLM: Multi-model SaaS gateways, Day-0 HuggingFace model onboarding, Multimodal vision/audio serving (`#65227`), and heterogeneous GPU clouds (NVIDIA + AMD ROCm + Ascend).
• Choose SGLang: Multi-turn Agents (`50%+` shared prefix via `RadixAttention`), structured JSON/Code generation, and DeepSeek V3/R1/V4 wide-EP MoE (`#49091`).
• Choose TensorRT-LLM: Homogeneous NVIDIA H200 / Blackwell GB200 clusters demanding absolute lowest single-request latency via fused CuTe DSL FP8/NVFP4 kernels.
• Enable PD Disaggregation (`Dynamo` + `Mooncake`): Clusters `≥ 16 GPUs` with `≥ 100G/400G RDMA` serving mixed `≥ 8K–128K` prompts under strict `P99 TPOT < 30 ms` SLAs.

⛔ Not For (Anti-Patterns to Avoid)

• Do NOT deploy PD Disaggregation on 1–8 GPUs or TCP-only Ethernet: Without RDMA (`RoCEv2`/`IB`/`EFA`), KV Cache network serialization takes longer than local Prefill compute.
• Do NOT use Co-located Chunked Prefill for 32K+ RAG + strict streaming chat: Prefill compute bursts still spike Decode P99 TPOT (`68.4 ms`), violating `< 30 ms` SLAs.
• Do NOT pick TensorRT-LLM for frequent weekly model swaps or non-NVIDIA GPUs: Engine compilation overhead and hardware lock-in outweigh kernel gains when models change weekly.

Production Architect Checklist (Before Customer Sign-Off)

1. Measure average prompt length & multi-turn prefix hit ratio (`≥50%` → enable Radix/APC).   2. Audit `nvidia-smi topo -m` & `ibv_devinfo` (`100G–400G RDMA` + `FI_HMEM`/GDR required for PD).   3. Separate `P95 TTFT` and `P99 TPOT` SLAs before sizing P:D node ratios (`1P:2D` or `2P:3D`).
