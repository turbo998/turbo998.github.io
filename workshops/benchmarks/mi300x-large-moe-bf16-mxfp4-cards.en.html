MY TAKE

Deploy BF16 for Production Throughput on MI300X; Use MXFP4 for 1-Node Density

✅ Good fit
  • 1-node 550B BF16 production serving: Nemotron 3 Ultra on 1x ND96isr_MI300X_v5 (TP8+EP8, 136.51 GiB/GPU) delivers 60.7 tok/s (C=1) and 317.4 tok/s (C=8)
  • 2-node 816B–975B BF16 serving: Muse Spark Open (348.6 tok/s @ C=8) and Inkling (335.8 tok/s @ C=8, 45 ms TTFT) via Ray TP8 x PP2 with NCCL_NET_GDR_LEVEL=0
  • 1-node 975B hardware consolidation: Quark MXFP4 fits Inkling 975B on a single 8-GPU MI300X node (66.74 GiB/GPU, 94.79 GiB free KV) for functional/batch evaluation
  • Ultra-large KV cache residency: Nemotron online MoE MXFP4 unlocks 111.86 GiB/GPU KV cache (13.76M tokens across 8 GPUs)
⛔ Not for
  • Interactive low-latency serving with MXFP4 on MI300X (gfx942 software FP4 emulation drops C=1 decode to 6.1–7.7 tok/s; use MI355X gfx950 or Blackwell for native FP4 speed)
  • Running Muse Spark Open in MXFP4 on MI300X (MuseSpark1x rejects EMULATION and requires native AITER_MXFP4_MXFP4)
  • Running TP16 or default GDR on 2-node Inkling 975B (sconv requires tp_size <= 8; default GDR hangs 16-rank RCCL)
  • Using default AITER MoE on Nemotron 3 Ultra without VLLM_ROCM_USE_AITER_MOE=0 (non-gated relu2 incompatibility)
