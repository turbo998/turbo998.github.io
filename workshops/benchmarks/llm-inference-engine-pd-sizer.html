LLM 推理引擎选型（vLLM vs SGLang vs TensorRT-LLM）与 PD 分离架构（NVIDIA Dynamo + Mooncake）— 架构师深度 FAQ 与定容计算器

对标 ib-vs-ethernet-roce-selection-faq.md 六段式结构：一针见血讲透何时选 vLLM、SGLang 或 TensorRT-LLM，以及何时用 NVIDIA Dynamo + Mooncake 实施 Prefill-Decode (PD) 分离（64×H100 DeepSeek-R1 671B 实测 3.08× 有效吞吐与 -67.5% 单 Token 成本）。

① 📌 核心结论速览（Executive Summary）

1. 单机 / 中小规模同机混部（≤8 卡）

通用多模型 SaaS 与新模型 Day-0 上线首选 vLLM v0.19.1；多轮 Agent、共享长 System Prompt 与 JSON 结构化输出首选 SGLang v0.5.10（RadixAttention 82% 命中率下 TTFT 提速 3.88×）；Blackwell/Hopper 固定主干模型压榨极限 FP8/FP4 TPOT 选 TensorRT-LLM v1.3.0（13.8 ms）。

2. 中大规模长上下文与 MoE 集群（≥32 卡 + RDMA）

当输入 ≥8K tokens 或并发 QPS 较高时，同机混部会发生 Prefill-Decode 干扰。采用 SGLang/vLLM + NVIDIA Dynamo v1.0.1 + Mooncake RDMA 实施 PD 分离，在 64×H100 DeepSeek-R1 671B 上实现 3.08× 有效吞吐（38,200 vs 12,400 tok/s）并将单百万 Token 成本从 $0.83 降至 $0.27（-67.5%）。

3. 核心技术本质：消除计算与访存干扰

Prefill 是算力密集型（Compute-Bound），Decode 是显存带宽密集型（Memory-Bandwidth-Bound）。PD 分离将两者拆到独立 GPU 池，通过 Mooncake GPUDirect RDMA 零拷贝（400G RoCEv2 下 18.4 ms 传输 420 MB KV Cache）彻底消除排队阻塞与注意力核气泡。
