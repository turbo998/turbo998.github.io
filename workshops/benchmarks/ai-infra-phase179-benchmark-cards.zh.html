六层架构，一条端到端关键路径

更快的 GPU 无法修复堵塞的网络、错误的 KV 布局或过低的有效工作可用率。沿六层关键路径定位瓶颈，再用原始计算器一次改变一个假设。

  1. 判断限制来自计算、HBM 容量、带宽还是排队。
  2. 沿 NVLink、跨机网络与 KV 交接跟踪字节量和所有权。
  3. 只重叠相互独立的任务，并检查瞬时显存与正确性。
  4. 在固定质量与尾时延 SLO 下评估每个有效词元的成本。

2 / 7场景：VLLM 逐层 KV 类型、SGLANG PD LINKER 与 MFSDP V2

逐层 KV 类型解析节省 43.75% 缓存，PD Linker 跳页减少 68.75% 冗余写入

输入案例（`64 层混合注意力 KV 缓存`、`16 页 PD 交接`与 `MFSDP v2 外层 DP`）

统一 BF16 KV 缓存为可使用 FP8 E4M3 的 56 个滑动窗口层分配了过多显存；PD 解码进程此前会把预填充已保存的 KV 页重复写入 Linker；MFSDP v2 外层 DP 梯度归约则在主计算流中串行执行。

决策 1 · vLLM 逐层 KV 类型（`#56155`）与 SGLang PD Linker 跳页（`#46395`） choice（选择）· 自动执行

逐层解析 `kv_cache_dtype`（`56 FP8 + 8 BF16` = 43.75% HBM 节省），在 PD 解码写入 Linker 时跳过已预填充的页（跳过 `11/16` = 68.75% 写入流量节省）。

决策 2 · Megatron MFSDP v2 外层 DP 流（`#6973`）与 MXFP8 双平面（`#8432`） score（评分）· 自动执行

使用独立 CUDA 流重叠外层 DP 梯度归约（84.0% 时延被隐藏， 1.18x 训练步加速），并为 MXFP8 重计算启用 `unshard_all_planes_in_backward`。

B200/B300 内核路由（`#8207` 与 `#2559`）： Kimi-K3 词元队列持久化路由实现 `1.18x` 加速（`33.04 -> 28.00 us`）；CuTe SM100 变长动态持久化调度达到 `1.29x`（占用率 `87.72%`）。

7 / 7工程判断 · 适用边界与就绪度

Rubin/Blackwell 内核、混合 KV 解耦与 MFSDP v2 训练架构手册

✅ 适用场景

  • Rubin `sm_107a` GDN CP 环修复（`#8206`）、B200/B300 Kimi-K3 词元队列路由（`#8207`）与 CuTe SM100 变长动态持久化调度（`#2559`）。
  • vLLM V1 逐层 KV 类型解析（`#56155`）、融合 MoE 填充跳过（`#64955`）与 `Qwen3.5-397B-A17B` B200 NVFP4 TP2（`#64607`）。
  • SGLang PD Linker 预填充页跳过（`#46395`）与 DSv4.1 整 SM 波次取整（`#47684`）。
  • Megatron MFSDP v2 独立外层 DP 流重叠（`#6973`），以及 MXFP8 的 `unshard_all_planes_in_backward`（`#8432`）。

⛔ 不适用场景

  • PD 解码进程将预填充已写入的 KV 页重复写回 Linker（`#46395`），或多个 DP 进程共用未偏移的 `kv_events` IPC 端口（`#47732`）。
  • MFSDP v2 MXFP8 激活重计算时仅对一个权重平面解除分片（`#8432`）。
  • TE THD CP 辅助内核静态分配共享内存（`#3698`），或多个 Mooncake UB 上下文尚在使用时提前销毁 `URMA` 模块（`#5104`）。
