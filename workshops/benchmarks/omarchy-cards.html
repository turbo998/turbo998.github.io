UNDER THE HOOD

From journald coredump to argv-safe agent launch

How Omarchy bridges systemd-coredump JSON events, D-Bus notification actions, and provider-pinned CLI execution without shell-evaluating untrusted crash metadata.

{
  "SYSLOG_IDENTIFIER": "systemd-coredump",
  "_UID": "1000",
  "COREDUMP_EXE": "/usr/bin/waybar",
  "COREDUMP_UNIT": "waybar.service",
  "COREDUMP_SIGNAL": "11",
  "COREDUMP_SIGNAL_NAME": "SIGSEGV",
  "COREDUMP_TIMESTAMP": "1787843905000000"
}
# omarchy-crash-watch packs NUL-delimited execArgv -> D-Bus ActionInvoked click required
↓ user clicks 'Investigate with AI' -> omarchy-agent-crash builds prompt & omarchy-launch-agent pins provider home
<crash_investigation_prompt>
Application: /usr/bin/waybar (waybar.service) · Signal: 11 (SIGSEGV)
Step 1: coredumpctl info 1787843905000000 + journalctl --since/@timestamp
Step 2: Identify root cause (config vs package update vs upstream bug)
Step 3: Propose fix and ask for confirmation before modifying files
</crash_investigation_prompt>
# omarchy-agent-account-exec claude -> exports OMARCHY_AGENT_CLAUDE_HOME & CLAUDE_CONFIG_DIR
# exec $1 "$@" -> claude --dangerously-skip-permissions "<prompt>" -> <answer>
Hard argv boundary up to CLI entry, followed by high-privilege CLI execution. Crash fields never pass through bash eval; notification-daemon invokes execArgv directly. However, once launched, the default harness receives --dangerously-skip-permissions / --yolo inside ~/Work, relying on prompt instructions to pause before edits.

MY TAKE

Where Omarchy's agent design shines, and where not to copy it

✅ Good fit
  • Single-user developer desktop unifying 14 heterogeneous agent CLIs behind one hotkey/terminal contract
  • Single-source-of-truth SKILL.md distribution via idempotent symlinks across multi-vendor agent directories
  • Human-in-the-loop OS crash triage: systemd-coredump filtering + notification click -> structured diagnostic prompt
  • Local multi-subscription quota pooling (95% threshold autoswitch + per-process credential home pinning)
  • Separating fast headless shell contract tests (test/all) from VM-only desktop acceptance tests
⛔ Not for
  • Multi-tenant or enterprise zero-trust environments requiring mandatory OS container/VM sandboxing
  • Treating ~/Work directory cd, --yolo flags, or SKILL.md 'ask before editing' text as a security boundary
  • Using local transcript token estimates or undocumented web/OAuth usage endpoints as authoritative billing
  • Assuming symlinked SKILL.md files are identically discovered and enforced by every third-party CLI
