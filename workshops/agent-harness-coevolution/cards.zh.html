SCENARIO · THE 12KB ROUTER CLIFF 2 / 7

故障根因：为什么 80 / 81 个用户技能对语义路由器彻底“隐身”？

Agent 运行时对系统提示词中的 <available_skills> 块实施约 12 KB（12,000 chars）硬上限保护，超限条目被静默剥离 description。

✕ 优化前：把正文章节塞进 YAML 描述

description: >
  Use this comprehensive skill whenever the user
  asks to create, polish, restructure, or review
  executive slide decks, customer workshops...
  (单条平均 476 chars · accessibility 单项达 1.1 KB)

✓ 优化后：≤140 字符高信噪比触发器

description: "构建微软 Azure Fluent 风格技术演示稿、架构评审 Deck 与 HTML/PPTX 视觉汇报页（含深浅色规范与版式栅格）。"

UNDER THE HOOD · PROGRESSIVE DISCLOSURE 4 / 7

渐进式披露重构：将 1,390 行单体大文件拆为 84 行路由树 + 按需模块

以 openclaw-wechat-deployment 为标杆案例，把首轮急切注入体积从 54.7 KB 压降至 3.4 KB（-94.0%），保护长链路推理注意力。

主入口 SKILL.md（≤120 行硬上限）只放什么？

  • 140 字以内的精准触发边界（何时用 / 何时不用）
  • 架构不变量与安全红线（如禁止明文硬编码密钥）
  • 阶段判定决策树 → 指向具体 references/*.md 路径

子目录 references/ & scripts/ 放什么？

  • 完整 Bicep / Docker Compose / Nginx 配置模板
  • 错误码与诊断命令对照矩阵（按症状索引）
  • 可确定性执行的校验脚本与字体/环境探测工具
设计范式切换：把 SKILL.md 当作“高内聚路由索引表”而非“百科全书”。Gemini 4 Carbon 与 GPT-6.2 Sol 擅长自主调用 view 读取所需分册。

ROBUSTNESS · FRONTIER MULTI-MODEL MATRIX 5 / 7

拆除跨代遗留拐杖 & 建立前沿多模型协同路由矩阵

彻底清除硬编码旧模型、虚构工具名与平台锁死路径，让当前主力模型阵列按认知比较优势分工。

已清除的三类历史遗留拐杖

  • 硬编码过时模型：删除 model: gpt-5.4 / gpt-4o-mini / claude-haiku-4.5，交由运行时 /subagents 动态路由。
  • 幻觉工具名称：将虚构的 search-the-web / fetch_page / runSubagent 修正为真实 web_search、web_fetch、task(...) 与原生 Canvases。
  • macOS 字体锁死：修复 invoice_edit.py 写死 PingFang.ttc 导致的 Windows/Linux 中文方框乱码（增加 msyh.ttc → NotoSansCJK → PingFang 回退链）。

MODEL-SKILL-MATRIX 四模型分工

  • Gemini 4 Carbon (long_context)：长仓综合、SVG 拓扑图解（anatomy / architecture-diagrams）、双语报告与 PPT/Web 产物。
  • GPT-6.2 Sol (high/xhigh/max)：复杂 Bicep/AKS 工程、OWASP/代码安全审计、严密 RPI 闭环与财务表格校验。
  • Grok 4.7 (high/xhigh)：实时热点竞品追踪（wechat-article / research）、Agent 红队对抗与线上故障秒级定界。
  • Gemini 3.8 Flash：高并发只读 explore / task 扫描。
# MODEL-SKILL-MATRIX.md 推荐协同流水线示例（架构评审 + 安全加固场景）
1. [Explore Sweep]  Gemini 3.8 Flash  -> 并行扫描全仓配置与依赖边界 (task: explore)
2. [Live Threat]    Grok 4.7 (high)   -> 检索最新 CVE 与 OWASP Agentic 攻击面 (web_search + owasp-agentic)
3. [Deep IaC Fix]   GPT-6.2 Sol (max) -> 编写并校验零信任 Bicep 策略与单测 (azure-prepare + azure-validate)
4. [Visual Deck]    Gemini 4 Carbon   -> 合成双语 SVG 架构图与管理层汇报 Deck (azure-style-presentation)

SCALING · THE INVERSE SCAFFOLDING LAW 6 / 7

反向脚手架定律：为什么基座模型越强，过程性提示词必须越薄？

跨越三代模型演进（GPT-4o → GPT-5.4 → Gemini 4 Carbon / GPT-6.2 Sol / Grok 4.7）的上下文治理定律。

关键上下文与预算缩放量化对照（Before vs After）

MY TAKE · PLAYBOOK FOR ENGINEERING TEAMS 7 / 7

团队实战指南：每次基座模型大版本升级必跑的五步 Harness 演进闭环

可直接复制到研发团队季度技术评审中的标准化 Agent Harness 持续体检清单。

1 · 遥测先行审计（Telemetry Audit）

切勿凭主观印象保留技能：定期查询 session_store_sql 的 tool_requests 调用表，揪出长期 0 调用的僵尸目录与跨目录重复插件。

2 · 9 KB 路由预算红线（Prompt Budget Guardrail）

将用户级 <available_skills> 总描述严格控制在 < 9 KB，单条 YAML description ≤ 140 chars，为动态工作区插件预留至少 3–4 KB 缓冲。

3 · 渐进式披露硬约束（Progressive Disclosure）

强制 SKILL.md ≤ 120 行 只写触发条件、红线不变量与阶段路由表；大段代码模板、Bicep 与排障手册全部下沉至 references/ 按需读取。

4 · 前沿模型重绑定与跨平台验证（Model Re-Binding）

删除硬编码旧模型名与虚构工具名，按任务特性路由至 Gemini 4 Carbon、GPT-6.2 Sol、Grok 4.7 与 Gemini 3.8 Flash，并验证 Windows/Linux/macOS 跨平台脚本兼容性。

5 · 自动化 CI 预算守门（Automated Regression Gate）

将总字符预算、单文件行数、禁用旧模型词表与重复技能名检测写入 CI 脚本，每次同步技能仓库自动拦截退化。
