七、出海制造客户高频深度追问与满分应答策略（8 大 Q&A）

Q1：企业核心 ERP 是 SAP S/4HANA（含 BW），海外还有 CRM 和各国代理商自己的系统，真实落地怎么接进 OneLake？

  • 满分应答：Fabric 提供三条成熟零侵入路径：
  1. SAP 体系：可通过 Azure Data Factory SAP CDC 连接器、SAP Datasphere 联邦/复制 或 Snowflake/Databricks Mirroring（数据库镜像） 准实时同步进入 OneLake Delta 表。
  2. 海外代理商 EDI 852 / 867（库存与实销）：代理商无需购买 Fabric 账号！只需按现有习惯通过 AS2/SFTP 或 API 投递到区域 ADLS Gen2 / 云端对象存储，总部用 OneLake Shortcuts 零拷贝挂载即可。
  3. 全渠道门店与社媒脉冲：通过 Fabric Real-Time Intelligence Eventstream 内置连接器无代码接入 Kafka、Azure Event Hubs 或 Webhook。

Q2：为什么这个场景一定要用 DirectLake，传统的 Power BI Import（导入模式）或 DirectQuery 不行吗？

  • 满分应答：全球跨时区大促期间，传统 Import 模式 每隔几小时全量刷新一次，数据总是滞后的且占双倍内存；而传统 DirectQuery 每次点切片器都现场查底层 SQL 数据库，高并发下极慢。DirectLake 是 Fabric 独有黑科技：语义模型直接把 OneLake 里的 V-Order Delta Parquet 列存按需映射进高速内存，既有 Import 的亚秒级响应速度，又有 DirectQuery 的实时更新能力，且零数据复制。

Q3：Fabric IQ Ontology（业务本体）和我们熟悉的 Power BI 语义模型（Semantic Model）到底有什么区别？

  • 满分应答：一句话总结——语义模型是为“人看报表做聚合（SUM/AVG）”设计的，而 Ontology 是为“AI 智能体理解真实世界实体、时序状态与行动护栏”设计的：
  1. Ontology 以业务对象为中心（如 ChannelPartner、OceanContainerShipment），天然生成 Property Graph 原生属性图（GraphModel），擅长多跳供应链影响面推导（货轮延误 → 分公司枢纽 → 下游代理商 → 受影响促销单）。
  2. Ontology 支持静态湖仓表 + 动态实时流（TimeSeries）双绑定，让同一个代理商实体同时具备静态授信额度和分钟级跳动的 DynamicWOS。
  3. Ontology 内置可被 Operations Agent 直接订阅的行动护栏规则，把“看数据”升级为“自动管业务”。

Q4：海外很多中小二级分销商没有 EDI 能力，只发格式五花八门的 Excel / CSV 邮件怎么办？

  • 满分应答：可将邮件附件自动落入 OneLake Files/ 原始着陆区（即本 Demo 展示的 Files/external_partner_edi_raw），利用 Fabric Data Pipeline + Notebook（或内置 AI Functions）自动完成列名标准化、SKU 映射清洗后合并入标准银层表，对上层 Ontology 完全透明。

Q5：欧洲分公司只能看欧洲代理商数据，不能看北美和拉美的底价与返利，权限怎么隔离？

  • 满分应答：Fabric 基于 OneLake Security + DirectLake 行级安全（RLS）/ 对象级安全（OLS） 实现统一管控。按 Entra ID 安全组绑定 SubsidiaryId（例如 SUB-EU-DE），无论是打开 Power BI 报表、使用 H5 门户，还是向 Fabric Data Agent 自然语言提问，Data Agent 都会严格继承当前登录人的身份令牌（Passthrough Auth），绝不会越权泄露其他大区敏感返利数据。

Q6：这个 H5 作战指挥舱在生产环境如何嵌入企业现有的海外业务门户、协同办公或 Teams？

  • 满分应答：本 H5 采用标准前后端分离架构，后端全部调用微软官方 GA 的 Power BI ExecuteQueries REST API、Kusto REST v2 API 与 Fabric Core Job Scheduler API。生产落地时只需接入企业 Entra ID SSO，即可无缝嵌入 Teams Tab、移动端企业协同工作台或海外经销商门户。

Q7：跑这样一套包含湖仓、实时流、Ontology 和智能体的环境，Fabric 容量成本大概多少？

  • 满分应答：这正是 Fabric 统一容量池（Unified Capacity CU） 的最大商业优势！今天演示的全套 16 个组件（Lakehouse + Eventhouse + DirectLake + Ontology + Graph + Data Agent + 2 个 Operations Agent + Spark Pipeline）全部运行在同一个 F8 容量上，无需分别为数仓、流计算、图数据库和 BI 购买四套独立集群。企业生产起步通常采用 F64（解锁免 Power BI Pro 许可证的全员分发能力），闲时还可弹性缩容。

Q8：如果客户想在 4 周内做一个真实的 PoC（概念验证），建议怎么切入？

  • 满分应答：建议聚焦 “1 个核心大区（如欧洲或拉美）+ 10 家头部国代/KA + 2 个刚性场景（大促断货跨仓调拨 + 老品价保风控）”：

  • 第 2 周：构建 ChannelPartner / Product / Inventory / Rebate 最小可行 Ontology 与 DirectLake 模型；
  • 第 3 周：上线 Data Agent 与 Operations Agent 预警推送至业务负责人 Teams；
  • 第 4 周：复盘拦截的潜在断货损失与价保节省金额，输出全球推广蓝图。
