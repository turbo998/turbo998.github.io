Crucial SA Routing Insight: Why phi-4-mini Runs on Adreno WebGPU While phi-4-mini-reasoning Runs on Hexagon NPU

In the live catalog, standard instruct phi-4-mini currently ships NO QNN NPU build—on Snapdragon X Elite it automatically routes to Adreno X1-85 WebGpuExecutionProvider (3.72 GB disk / 3.74 GB VRAM). By contrast, phi-4-mini-reasoning ships a native QuaRot + GPTQ QNN package (2.78 GB) that executes directly on the 45 TOPS Hexagon NPU (Priority 0) while saving 25.3% memory!

.NET 10 WinML In-Process Core API, Python SDK & CLI v0.14.0 Quickstart

For production Windows client apps, prefer the in-process WinML Core API (Microsoft.AI.Foundry.Local.WinML or foundry-local-sdk-winml)—adding only ~20 MB runtime overhead with zero background daemon management:

Four Production Engineering Pitfalls (Field-Verified SA Playbook)

Pitfall 1: .NET 10 Generic TFM Breaks WinML Dynamic EP Registration

Scaffolding a project with bare <TargetFramework>net10.0</TargetFramework> omits Windows WinRT/WinML projections, causing dynamic IHV EP discovery to fail or silently fall back to CPU. Fix: Target a Windows-specific TFM such as net10.0-windows10.0.26100.0 (or net8.0-windows10.0.22621.0) and set an explicit <RuntimeIdentifier>win-arm64</RuntimeIdentifier> (or win-x64).

Pitfall 2: Silent EP Divergence Between phi-4-mini and phi-4-mini-reasoning

Assuming every phi-4-mini* alias runs on NPU leads to unexpected GPU load: phi-4-mini (instruct) has only WebGPU (3.72 GB disk / 3.74 GB VRAM) and CPU builds, whereas phi-4-mini-reasoning (2.78 GB, QuaRot + GPTQ) runs natively on Hexagon NPU. Fix: Pin background low-power agents explicitly to phi-4-mini-reasoning, phi-3.5-mini (2.02G), or qwen2.5-coder-1.5b (1.06G).

Pitfall 3: Unified Memory Commit Pressure & QNN Error 5005 on 32 GB Systems

On unified LPDDR5x Copilot+ PCs, even when Task Manager shows "Available physical RAM", heavy browser/IDE/container workloads can push Windows Commit Charge near the Commit Limit, causing Hexagon QNN contiguous buffer allocation for 7B/14B models to fail with QNN error 5005. Fix: Keep ≥ 10 GB uncommitted headroom before loading deepseek-r1-14b (7.12G), allow system-managed pagefile growth, and unload idle model sessions promptly.

Pitfall 4: foundry-local-sdk-winml vs. foundry-local-sdk Namespace Collision

Both Python packages share the exact foundry_local module namespace, but only foundry-local-sdk-winml includes Windows ML dynamic EP registration. Installing both in the same virtualenv corrupts package files and strips NPU discovery. Fix: Use a clean venv and run pip uninstall -y foundry-local-sdk foundry-local-sdk-winml before installing foundry-local-sdk-winml alone.
