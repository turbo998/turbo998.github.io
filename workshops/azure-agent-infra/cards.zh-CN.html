✅ 适用场景
  • Foundry托管代理 : 使用核准的API的To-B业务代理商& 1,400+ MCP连线器与最小的以下行动。
  • Durable Functions + ACA应用 : 需要等待外部活动的长期采购/财务/核准流动&决断再演.
  • ACA动态会话/ 沙盒 : 以弗比的超V代码执行( E)`~210ms`)或状态编码/浏览工作空间并带有暂停/重现快照.
  • AKS+ 卡塔( 双向)`AKSClaw`): 多租户工程/SRE车队需要BYO的接头、共享技能市场,以及5硬平台边界。
  • E2B有关自愿服务制度(`D96as_v7`): 需要的AI-原生产品100K+ 并行虚拟计算机,位于`108ms–132ms`启动。
⛔ 不适用场景
  • 跟踪未得到满足的控制需求Foundry: 永远不要将需要自定义的OS/network/sandbox控制器的客户推入Foundry主办代理公司只是因为他们缺少一支Dev团队(不如参与CSU/Partner).
  • 只在动态会话中存储持久状态 : 闲置的开垦工地将擦去地方储存;在其中始终设有检查站 Azure地平线DB 或 减 减 Cosmos DB.
  • 盲目CPU缩放在E2B虚拟管理系统: Firecracker消耗大页; 缩小范围, 不消耗大页排出&活地迁徙杀死活地沙盒.
  • 内插LLM密钥或继承的用户符号 : 永远不要挂起静态API代理容器中的密钥或让代理继承完整的用户代号。
