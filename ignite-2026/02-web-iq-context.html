关键架构设计决策 · Key Architectural Decisions Key Architectural Decisions

  • 受控预算证据抽取替代整页 HTML 注入：默认以 30,000 字符上限返回清洗后的高相关段落与结构化 JSON，避免原始网页 DOM 噪声引发长窗口注意力衰减（Lost-in-the-Middle）与无效 Token 消耗。
  • 检索前作用域校验与控制面 RBAC 分离：Exclude 规则具备最高优先级并强制启用 failOnMissingScope=true；通过独立 CustomerApiAccess 数据面角色防止应用运行时密钥篡改域名白名单。
  • 按查询复杂度分层路由：单跳实时事实与实体查询路由至 Auto ($8/1K) 或结构化垂直 API ($7/1K)；跨多源交叉核验任务路由至服务端闭环的 Auto Advanced ($9/1K)。
  • Health 医疗垂直域合规边界：Health 端点按美国国家医学科学院（NAM）标准加权权威临床信源，但不签署 HIPAA BAA，架构上必须在网关侧前置剥离全部患者可识别健康信息（PHI）。
  • Bounded Passage Extraction Over Raw DOM Injection: Returns sanitized, cited passages within a 30,000-char budget plus structured JSON—preventing 100K-token HTML noise and Lost-in-the-Middle degradation.
  • Pre-Retrieval Scope Filtering & RBAC Separation: Enforces Exclude precedence and failOnMissingScope=true; isolates runtime CustomerApiAccess keys from control-plane scope administration.
  • Complexity-Tiered Retrieval Routing: Directs single-hop lookups to Auto ($8/1K) or domain APIs ($7/1K), reserving server-side multi-hop Auto Advanced ($9/1K) for multi-source synthesis.
  • Health Endpoint HIPAA Boundary: Health ranks NAM-aligned clinical authorities but is excluded from HIPAA BAA coverage, requiring mandatory pre-flight PHI redaction at the gateway.

架构集成优势 · Platform Integration Rationale Platform Integration Rationale

  • 亚秒级延迟与下游上下文压缩协同：结合服务端相关性裁剪与 Microsoft-Retriever-1（0.76s 中位延迟，削减 83.6% 下游输入 Token），显著降低端到端推理时延与成本。

02.1 · CONTEXT ENGINEERING METHODOLOGY

生产级上下文工程四大架构法则 Four Architectural Principles of Context Engineering

诊断企业 Agent 幻觉与上下文 Token 膨胀的四大根因，采用“高信噪比段落抽取 + 内外部数据源分层解耦 + 检索前作用域过滤 + 服务端自适应多跳验证”替代客户端原始网页抓取。 Diagnose the four root causes of enterprise agent hallucination and token bloat, replacing naive scraping with high-SNR extraction, external/internal data-plane decoupling, pre-retrieval scoping, and server-side multi-hop verification.

Architecture First
🎯 架构师讲解导引：先做根因诊断，再对齐服务选型 Presenter Framing: Diagnose Root Causes Before Pitching APIs

面向合作伙伴 SA 讲解时，避免将 Web IQ 简单表述为传统网页搜索接口。先通过以下 4 项工程根因展开分析：为何自建 SerpAPI + Playwright 抓取整页 HTML 注入 128K 上下文窗口会导致 Lost-in-the-Middle 注意力衰减与间接提示词注入？明确四项上下文工程原则后，Web IQ（公开域实时信号）与第三章 Fabric Ontology（企业内域受控语义）的边界便一目了然。

Avoid framing Web IQ as just another search API. Lead with these 4 engineering diagnostics: explain why DIY SerpAPI + headless HTML scraping degrades under Lost-in-the-Middle attention dilution, 100K-token DOM bloat, and indirect prompt injection. Once those four design principles are established, pairing Web IQ (external public signals) with Fabric Ontology (internal enterprise data, Stage 03) becomes a clear architectural boundary.

病灶 ① 静态知识截断失明 Root Cause 1 · Cutoff Blindness

模型预训练权重对突发关税政策、港口台风停航、监管新规与竞品当日调价完全失明，强答必然产生高危商业幻觉。 Frozen model weights are blind to intraday tariff shifts, port typhoons, regulatory filings, and live competitor SKU promos—forcing confident fabrication.

病灶 ② 脏 HTML 噪声与中间迷失 Root Cause 2 · HTML Noise & Bloat

粗暴抓取整页 DOM（导航栏/广告/脚本）动辄灌入 100K+ Tokens，触发 Lost-in-the-Middle 注意力稀释并令首字延迟飙升 5–10 倍。 Dumping raw scraped DOM boilerplate burns 100K+ tokens per turn, triggering Lost-in-the-Middle attention decay and spiking TTFT.

病灶 ③ 非受控信源与提示词注入 Root Cause 3 · Ungoverned Sources

无白名单约束的全网检索极易混入内容农场、营销软文与恶意隐藏指令（Indirect Prompt Injection），污染决策链路甚至诱导数据外泄。 Unscoped web scraping ingests SEO farms, unverified forums, and indirect prompt-injection payloads straight into autonomous tool loops.

病灶 ④ 后置鉴权越界与多跳断裂 Root Cause 4 · Post-Filter & 1-Hop Failure

检索后再靠应用层过滤权限既脆弱又易返回空集；而单次向量召回面对复合商业推演题往往漏掉关键二跳/三跳跳板证据。 Fragile post-retrieval ACL filters leak or starve top-k results, while single-pass lookups fail compound multi-hop business questions.

法则 1 & 2：高信噪比切片 + 内外部数据源分层解耦 Principles 1 & 2: High-SNR Passages + External/Internal Decoupling

避免向大模型直接输入整页原始文档或网页 DOM——在明确字符/Token 预算（如 Web IQ 默认 30,000 字符）内仅提取高密度带引用证据块或结构化实体 JSON；同时在架构上将外部公开域实时信号（Web IQ）与企业内域协作记忆及业务本体（Work IQ + Fabric IQ）解耦治理、按需联邦检索。 Never feed raw HTML or unchunked documents into the prompt window—extract dense cited passages or typed entity JSON within bounded budgets (e.g., 30,000-char default), while cleanly decoupling external public signals (Web IQ) from governed internal enterprise memory & ontology (Work IQ + Fabric IQ).

法则 3 & 4：索引内前置护栏 + 服务端自适应多跳 Principles 3 & 4: Pre-Retrieval Scoping + Adaptive Multi-Hop

把可信域名白名单与文档 ACL 下沉到检索引擎排序之前执行（Web IQ Scopes + Foundry IQ 原生 SharePoint/OneLake ACL），杜绝后置过滤失真；简单问题走单趟低延迟通道，复杂研究问题交由检索引擎服务端自动完成子查询改写与证据充分性校验（Auto Advanced），免去客户端多轮 LLM 往返开销。 Enforce trusted domain allow/block lists and SharePoint/OneLake ACLs inside the retrieval index before ranking—never via brittle post-filters—and pair fast single-pass lookups with server-side iterative query decomposition and sufficiency verification for compound research tasks.

企业级零信任护栏：Scopes（免费内置）+ 零日志合规 + 三态接入面 Enterprise Security & Governance: Free Scopes + Zero Query Logging + 3 Integration Surfaces

1. 万级域名精细收敛（Exclude Wins） 1. 10K + 10K Domain Selectors

单 Scope 免费支持高达 10,000 条允许 + 10,000 条屏蔽域名/URL 路径前缀规则（Web/News 已 GA，Auto 中 Preview）。规则重叠时屏蔽绝对优先（Exclude Always Wins），且默认开启 failOnMissingScope=true 故障闭合保护。 Up to 10,000 allowed + 10,000 blocked domain/URL-prefix rules per scope at zero extra cost (GA on Web/News; Preview in Auto). Exclude always wins on overlap, with failOnMissingScope=true fail-closed protection by default.

2. 控制面/数据面权限隔离 + 零日志 2. Role Separation & Zero Query Logging

Scope 策略变更由独立的 Entra CustomerApiAccess 角色管控，运行时 Agent 推理密钥无法修改或删除护栏；金融投行、并购尽调等强监管客户可申请开启 Zero Query Logging（零查询日志留存）。 Control-plane edits require the separate Entra CustomerApiAccess role so runtime agent keys cannot weaken or delete scopes; regulated financial/M&A workloads can enable optional Zero Query Logging.
