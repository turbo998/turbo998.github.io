Design points · 架构师关键设计决策 Design points / Solution Architect Decisions

  • 将治理边界延伸至开发者与员工终端：仅监控云端 API 网关无法覆盖本地 CLI 工具链，须结合终端发现能力纳管 35 类本地 Agent 与未注册 MCP 进程。 Extend governance from cloud gateways to endpoints: Cloud-only API logs miss workstation tools; combine cloud inventory with endpoint discovery across 35 local CLI and MCP runner classes.
  • 解耦 DLP 上线前置条件与历史文件打标工程：启用 Purview Unlabeled DLP 内容级分类与 MCP Firewall 协议拦截，避免因存量文档缺少密级标签而阻塞上线。 Decouple Day-1 DLP protection from historical labeling backlogs: Pair inline Purview Unlabeled DLP classifiers with MCP Firewall allowlists so unlabeled legacy files do not block production launch.
  • 建立基于业务结果的 FinOps 治理指标：以“单笔有效业务成果成本（Cost per Validated Outcome）”替代单纯 Token 消耗监控，作为扩容配额或下线低效实例的量化依据。 Standardize FinOps on Cost per Validated Outcome: Evaluate agent fleet ROI by linking Azure infrastructure spend to completed business transactions rather than raw token volume alone.
  • 依托 CSP 多租户架构构建可复用托管服务（MSP）：合作伙伴可通过标准化策略模板跨多个客户租户统一维护身份生命周期、MCP 白名单与月度合规审计。 Standardize Partner MSP operations via CSP Multi-Tenant: Manage cross-tenant identity lifecycles, MCP allowlists, and monthly compliance/FinOps reviews from a single delegated console.
