STAGE 01 · UNIFIED AGENT ENTRY

调用与控制流 · Request & Control Flow (1–6) Request & Control Flow (1–6)

  1. 终端用户或嵌入式宿主应用按任务时长选择 Chat / Cowork / Autopilot / Code 发起请求或异步委托。
  2. Copilot Standalone（2026-12-01）通过 Entra OIDC/SAML 联邦对接客户既有飞书/钉钉/Okta IdP，无需前置采购 M365 基础套件。
  3. 请求经 Front Door + APIM (MCP Gateway) 完成 WAF 校验、速率配额控制及 OAuth 2.0 OBO 用户级委托令牌交换。
  4. Copilot Studio、预置 MCP 插件与 Functions Adapter 执行协议转换、Idempotency-Key 幂等去重与读写路由分离。
  5. 只读通道（Read Path）严格携带当前用户委托权限拉取飞书/钉钉文档纪要与 Salesforce/ServiceNow 业务实体。
  6. 事务回写通道（Write Path）针对 SAP/ERP 订单变更强制下发 Adaptive Card 人工审批，确认后提交事务并写入 Agent 365 审计日志。
  1. End users or embedded host apps initiate synchronous queries or async delegations through Chat / Cowork / Autopilot / Code.
  2. Copilot Standalone (Dec 1, 2026) federates existing Feishu/DingTalk/Okta IdPs via Entra OIDC/SAML without requiring M365 base licenses.
  3. Front Door + APIM (MCP Gateway) enforces WAF rules, rate quotas, and user-delegated OAuth 2.0 OBO token exchange.
  4. Copilot Studio, prebuilt MCP plugins, and Functions Adapter handle protocol mediation, Idempotency-Key checks, and read/write separation.
  5. Read Path retrieves Feishu/DingTalk context and Salesforce/ServiceNow records strictly within the caller's delegated ACLs.
  6. Write Path gates SAP/ERP state mutations behind Adaptive Card human approval and records immutable audit trails in Agent 365.

关键架构设计决策 · Key Architectural Decisions Key Architectural Decisions

  • 按执行语义划分四种模式：同步低延迟问答走 Chat；复杂文档结构化交付走 Cowork；跨日异步值守走绑定独立 Entra Agent ID 的 Autopilot（需 Frontier + Agent 365 许可）；定制前端交互走 Code。
  • 许可层与身份层解耦（12/01）：区分 2026-12-01 Standalone 许可解绑与 FY27 Q3 CSP 默认启用 UBB 按量计费两项机制，支持在不迁移存量 IM/OA 的前提下分阶段上线。
  • 禁用共享高权限静态凭据：全链路采用用户级 OBO 令牌透传最小权限；外部系统写操作强制实施“预检预览 → 人工确认 → 幂等提交”两阶段协议。
  • 多语言运行时内核统一：Copilot SDK 2.0 基于单一 Rust 核心封装 Python、TypeScript、.NET、Java、Go 等 6 语言接口（GA），避免原型与生产双栈重写。
  • Execution-Model Partitioning: Route low-latency Q&A to Chat, structured document authoring to Cowork, persistent async jobs to Autopilot (with dedicated Entra Agent ID), and custom micro-apps to Code.
  • Licensing & Identity Decoupling (Dec 1): Separates Dec 1, 2026 Standalone seat decoupling from FY27 Q3 CSP UBB default-on billing, enabling phased adoption alongside existing IM/OA tools.
  • Eliminate Shared Service-Account Secrets: Enforces user-delegated OBO tokens on all reads and a two-phase preview → human sign-off → idempotent commit protocol on ERP writes.
  • Single Native SDK Runtime: Copilot SDK 2.0 wraps one Rust core across 6 languages (GA), removing Python-to-.NET/Java/Go rewrite overhead for ISVs and enterprise teams.

架构集成优势 · Platform Integration Rationale Platform Integration Rationale

  • 原生 OOXML 文档结构保真：Office in Copilot 直接操作原生 .docx/.xlsx/.pptx 对象模型（含公式、透视表与企业母版），避免纯文本导出导致的格式失真。
  • 非人主体身份与未打标内容 DLP 联动：Entra Agent ID 为后台智能体提供独立身份审计，配合 Purview 内容级检测实时拦截未打标敏感文档越权引用。
  • 跨生态 MCP 工具契约复用：D365 (100+ GA) 与 Salesforce (38+ Preview) 预置插件基于统一 MCP 网关治理，可在 Copilot 与自建智能体间直接复用。
  • 受管沙箱与配额集中治理：Managed Runtime + Agent 365 统一收敛业务自建微应用的运行时隔离、API 审计与部门级消费上限。
  • Native OOXML Document Fidelity: Office in Copilot manipulates native .docx/.xlsx/.pptx object graphs (formulas, PivotTables, corporate slide masters) without lossy markdown conversion.
  • Non-Human Principal Identity + Content DLP: Pairs dedicated Entra Agent ID principals with inline Purview content inspection to block unauthorized use of unlabeled sensitive files.
  • Reusable Governed MCP Tool Contracts: Prebuilt D365 (100+ GA) and Salesforce (38+ Preview) plugins register once behind APIM MCP Gateway for reuse across agents.
  • Centralized Sandbox & Quota Governance: Managed Runtime + Agent 365 unifies runtime isolation, audit logging, and departmental UBB budget caps for user-built apps.

⚙️ 架构机制 · Architecture Mechanics Architecture Mechanics
  • 身份联邦免迁移：通过 Microsoft Entra ID 与客户现有 IdP（飞书/钉钉企业认证、Okta、Google Identity）建立 OIDC/SAML 联邦，无需搬迁存量邮箱与即时通讯记录即可开通 Copilot Standalone。
  • 预置插件 + 标准 MCP 协议层：开箱即用调用 Dynamics 365 Sales/ERP（GA，100+ 技能）与 Salesforce in Copilot（Preview，38+ 技能），对自建 ERP/飞书审批统一封装为标准 MCP Server。
  • APIM OBO 读写分离：查询通道采用 Entra On-Behalf-Of（OBO）透传用户级权限，杜绝共用高权 Service Principal 导致越权；写入通道强制经 Copilot Studio 审批卡片人工确认后由 Logic Apps 幂等提交。
  • Zero-Migration Identity Federation: Federate Microsoft Entra ID with existing IdPs (Google Identity, Okta, Feishu/DingTalk SSO) via OIDC/SAML—activating Copilot Standalone without migrating legacy mail or chat archives.
  • Prebuilt Business Plugins + Standard MCP: Leverage turnkey Dynamics 365 Sales & ERP (GA, 100+ skills) and Salesforce in Copilot (Preview, 38+ skills), while wrapping custom ERP/OA APIs behind reusable MCP Servers.
  • APIM OBO Read/Write Separation: Read paths enforce user-scoped Entra On-Behalf-Of (OBO) tokens (never over-privileged shared service keys); write paths require explicit human confirmation cards and idempotent Logic Apps execution.

⚔️ 竞争优势 · Competitive Advantage Competitive Advantage
  • 对比 Slack AI / 飞书智能伙伴 / Google Gemini Workspace：竞品深锁在单一 IM 或网页文档内，无法原生生成带复杂财务公式与透视表的行业标准 .xlsx/.pptx，更缺乏跨多云 Agent 的 Agent 365 统一审计与成本封顶。
  • 对比垂直 SaaS 自带 Bot（Salesforce Agentforce 等）：单一 SaaS Bot 受限于自有库表且按会话计费，难以贯通 CRM 业务数据与正式办公文档之间的交付链路；Copilot 同时编排跨系统 CRM/ERP 技能与原生 Office 文档生成。
  • 对比开源自建 Dify / LangChain 门户：省去重复造轮子的身份鉴权、多模型动态路由、Office 渲染引擎与未打标敏感文件 DLP 拦截底座。
  • vs. Slack AI / Google Gemini Workspace / Local OA Bots: Rivals are trapped inside chat threads or web docs—unable to natively author complex financial .xlsx PivotTables/decks or govern multi-cloud agents under Agent 365.
  • vs. Siloed SaaS Bots (e.g., standalone CRM bots): Single-SaaS bots are blind outside their own database and cannot bridge the "last-mile deliverable gap" into editable Word/Excel/PowerPoint client artifacts.
  • vs. DIY Open-Source Agent Portals: Eliminates months of custom plumbing for OBO token exchange, Auto model routing, native Office co-authoring, and Purview DLP protection on unlabeled files.
