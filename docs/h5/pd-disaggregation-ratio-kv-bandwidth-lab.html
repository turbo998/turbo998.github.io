3 分钟看懂核心结论：为什么静态 1:1 切池必亏 35% 算力？如何手算最佳 P:D 配比与 RDMA KV 带宽？

核心铁律：① Prefill 算力受限（Compute-Bound）与 Decode 显存带宽受限（Memory-BW-Bound）混部会产生严重尾延迟抢占；② 最佳实例配比满足 $N_P / N_D = [\text{RPS}\cdot S_{\text{in}}(1-\eta)/\text{TPS}_P] \div [\text{RPS}\cdot S_{\text{out}}/\text{TPS}_D]$，白天长文 RAG（`5P:3D`）与夜间深度推理 CoT（`2P:6D`）发生倒转，必须保留 `25% Flex` 零重启双模节点；③ DeepSeek MLA (`35.1 KB/tok`) 比 70B GQA-8 (`163.8 KB/tok`) 跨机 KV 传输体积小 `4.67 倍`，配合 400G GPUDirect RDMA 逐层流水线重叠可将暴露延迟压至 `2.4 ms`！

3-Minute Executive Takeaway: Dynamic P:D Ratio Math, Heterogeneous GPU Pairing & Layer-Wise RDMA KV Transfer

Golden Rules: (1) Static 1:1 PD pools strand 35% of GPUs when traffic shifts between daytime RAG (5P:3D) and nighttime CoT reasoning (2P:6D); reserve 25% Flex zero-restart workers. (2) Pair compute-dense GPUs (H100) for Prefill with bandwidth-dense GPUs (H200) for Decode. (3) DeepSeek MLA shrinks KV transfer by 4.67x vs. 70B GQA-8 (2.4 ms exposed over 400G RDMA).

🧠 架构师三大核心拷问与主流 PD 框架（Dynamo NIXL / Mooncake / SGLang / LMCache）选型矩阵

拷问 1：为什么我们的 RAG 集群白天 Prefill 排队超时，一到晚上跑 DeepSeek-R1 思维链却变成 Decode 显存打满？

因为白天 RAG 是典型长输入短输出（16K:400），单请求耗费在 Prefill 上的标准节点秒是 Decode 的 `1.62 倍`（需 `5P:3D`）；而夜间深度推理是短输入超长思维链输出（2K:4K），Decode 耗时反超 Prefill `5 倍`（需 `2P:6D`）。通过将 25% 节点配置为 Flex 双模节点（无需重载权重，秒级切换网关路由标签），可将全天闲置率从 `35%` 压至 `3.2%`。

拷问 2：为什么 DeepSeek 671B 做跨机 PD 分离反而比 70B Dense 模型更轻松？

因为 DeepSeek 采用 MLA（多头潜注意力），将每层 KV Cache 压缩为仅 `576` 个元素，61 层全模型每 Token 仅 `35.14 KB`（FP8），比 70B GQA-8（`163.84 KB/tok`）小 **`4.67 倍`**！一条 16K 请求只需传 `0.56 GB`，在 400G RDMA 逐层重叠下净暴露传输延迟仅 **`2.4 ms`**。
