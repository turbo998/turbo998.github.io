Map far plane to 0.0 via d = z_near / z. Stop distant Forward-Z decal Z-fighting.

为什么在大尺度城市数字孪生、飞行模拟跑道或远景建筑群渲染中，当近裁剪面设为 z_near = 0.10 m 时，哪怕你已经开启了 32 位浮点深度缓冲（DEPTH_COMPONENT32F），4096 米外相距 25 厘米（0.25 m）的墙面与广告牌贴花依然会疯狂互相穿模闪烁（“Z-Fighting 深度冲突”）？因为传统的正向 Z 映射（Forward-Z: d = 1.0 − z_near / z）把所有远景都挤在 1.0 附近，在做 `1.0 − 0.0000244` 减法时发生了灾难性的浮点有效位数抵消，将最小精度间距锁死在 1 ULP = 2⁻²⁴，导致 4096 米处的最小可分辨深度间隔恶化至 10.00 米！而反转 Z 浮点深度缓冲（Reversed-Z: d = z_near / z，Near → 1.0, Far → 0.0）省去了 `1.0 −` 减法，直接利用 IEEE-754 浮点数在 0.0 附近随指数自动缩小的动态精度，在 4096 米处实现 0.00031 米（0.31 毫米）分辨率，精度飙升 32,768×！An original 13-octave 3D optical rangefinder bench compares Reversed-Z float32 depth mapping against standard Forward-Z Z-fighting collapse.

Perspective float32 Reversed-Z depth mapping is not monocular depth estimation / 反转 Z 浮点透视深度映射不等于单目深度估计推理

This bench evaluates deterministic IEEE-754 binary32 (`Math.fround`) Reversed-Z perspective depth mapping d = z_near / z versus standard Forward-Z mapping d = 1 − z_near / z across 13 distance octaves (1 m to 4,096 m). It does not execute Depth Anything, Marigold, or monocular neural depth estimation models.

在近裁剪面 z_near = 0.10 m、墙面与贴花间距 δz = 0.25 m（25 厘米）的第 12 号远景站点（z = 4096 m）处：反转 Z（Reversed-Z）将深度映射至 d = 2.4414e−5，触发 float32 指数下移至 2⁻¹⁶，最小可分辨间距达 0.00031 m（0.31 毫米，精度提升 32,768×，全 13 个距离倍频程 0 次 Z-Fighting）；而传统正向 Z（Forward-Z）因 `1.0 − z_near/z` 挤压在 1.0 附近，最小可分辨间距恶化至 10.00 m，导致 0.25 m 贴花在远景发生 Δd = 0 的完全深度坍缩（后 3 个倍频程站点 1024m~4096m 全部触发 Z-Fighting 穿模）！
