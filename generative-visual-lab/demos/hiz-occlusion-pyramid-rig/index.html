Reduce Hi-Z mip levels by farthest depth max(z). Stop average-depth mips popping doorway objects out of existence.

为什么在 GPU 驱动的遮挡剔除（GPU-Driven Occlusion Culling，如 Unreal Engine 5 Nanite、Frostbite 与 Unity GPU Resident Drawer）中，构建多级层次深度金字塔（Hierarchical-Z / Hi-Z Pyramid）时，**绝对不能调用普通的硬件均值降采样 `generateMipmap()`**？设想一面距离相机 `z_wall = 4.0 m` 的近景墙体覆盖了一个 `8×8`（64 像素，Mip 3）图块，墙上有一道仅 `4` 个像素宽的门缝或铁栅栏间隙，透过门缝能看到 `z_gap = 50.0 m` 处的走廊尽头；而在门缝后方 `z_obj ∈ [6.0, 46.0] m` 处站着 17 个透过门缝清晰可见的角色或道具！如果用算术平均构建 Mip 3 深度，60 个近墙像素（`4.0 m`）与 4 个门缝像素（`50.0 m`）被平均成 `z_avg = 6.8750 m`——导致凡是站在 `z_obj > 6.8750 m`（第 1~16 站，共 `16/17` 即 `94.12%`）的可见角色全部被判定为“在墙体后面”而遭到**错误剔除消失（False Occlusion Popping）**！而 Ned Greene 等人（SIGGRAPH 1993）提出的保守最远深度归约 `z_HiZ = max(z_0 .. z_63) = 50.0000 m`（在 Reversed-Z 下对应 `min`），严格保证：**只要图块里哪怕有 1 个像素还没挡住，整块 Mip 的遮挡阈值就取最远的那 1 个像素**，从而 100% 保留门缝后方全部 `17/17` 个可见物体（`0` 误剔除闪崩），且单次 Mip 3 查表比扫描 64 个全分辨率像素快数十倍！An original 17-station 3D occlusion collimator bench compares Greene conservative `max(z)` Hi-Z pyramid culling against naive average-mip false occlusion popping.

Conservative Hi-Z pyramid culling is not neural visibility prediction / 保守层次深度金字塔剔除不等于神经可见性预测推理

This bench evaluates deterministic Ned Greene et al. (SIGGRAPH 1993) conservative farthest-depth Hierarchical-Z (Hi-Z) mip reduction (z_HiZ = max(z_0..z_63)) versus naive box-average depth mipmapping and brute-force 64-pixel full-resolution tile scanning across 17 object depth stations (z_obj ∈ [6.0, 46.0] m) behind a 4-pixel doorway slit. It does not execute neural visibility or PVS prediction networks.

在包含 60 个近景墙体像素（`z_wall = 4.0 m`）与 4 个远景门缝像素（`z_gap = 50.0 m`）的 `8×8`（Mip 3）深度图块后方，依次检验第 0~16 站（`z_obj = 6.0 .. 46.0 m`）透过门缝可见的物体时：Greene 保守最远深度归约锁定 `z_HiZ = max(4.0, 50.0) = 50.0000 m`，100% 保留全部 `17/17` 个门缝后方可见物体（`0` 误剔除闪崩）；而朴素均值深度 Mip 将阈值拉低至 `z_avg = 6.8750 m`，导致第 1~16 站共 `16/17`（`94.12%`）个清晰可见的物体被错误当成被遮挡物整块剔除消失！
