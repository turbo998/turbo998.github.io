为什么在自定义软光栅化器、WebGPU 计算着色器光栅管线（Visibility Buffer UV 解包）或经典初代 PlayStation 3D 渲染中，如果直接用屏幕空间的 2D 重心坐标对顶点 UV 做线性插值 `u_affine = (1 − s)·u₀ + s·u₁`，大透视倾角的地面棋盘格与墙面贴图会沿着三角形对角线发生剧烈的折断扭曲，并在镜头旋转时像果冻一样来回晃动（“仿射纹理游动 Affine Texture Swim”）？因为透视投影除以了齐次深度 `w_clip = z`，世界空间坐标 `u` 在屏幕空间是双曲线而非直线！真正满足屏幕空间线性不变性的是倒数深度 `1/z` 与透视预除属性 `u/z`（Heckbert & Moreton 1991）。当顶点跨越近端 `z₀ = 1.0 m` 到远端 `z₁ = 9.0 m` 时，屏幕正中央 `s = 0.50` 对应的真实三维地面位置其实在 `z = 1.80 m`（真实 `u = 0.1000`），而屏幕仿射插值却盲目输出 `u = 0.5000`（畸变高达 +0.4000 / 相对误差 +400%）！An original 17-station 3D perspective interpolation bench compares hyperbolic `(u/w)/(1/w)` interpolation against screen-space affine texture swim.

Projective reciprocal-W interpolation is not neural view warping / 透视双曲倒数插值不等于神经新视角合成推理

This bench evaluates deterministic Heckbert & Moreton (1991) / Blinn (1992) projective `(u/w) / (1/w)` hyperbolic attribute interpolation versus naive screen-space affine interpolation and 3D ray-plane intersection across 17 screen-space stations. It does not execute neural homography or view-synthesis models.

在近端深度 z₀ = 1.00 m（u₀ = 0.0）、远端深度 z₁ = 9.00 m（u₁ = 1.0，深度透视比 9:1）的第 8 号屏幕中心站点（s = 0.5000）处：透视正确双曲倒数插值先线性插值 1/z = 0.5556 m⁻¹ 还原出真实世界深度 z = 1.8000 m，并精确算出纹理坐标 u = 0.1000（全 17 站 0.0000 纹理游动误差，预计算顶点倒数较逐像素 3D 射线-平面求交快 17.22×）；而朴素屏幕空间仿射插值在 s = 0.5000 处直接输出 u = 0.5000（中点偏移 +0.4000，全场最大畸变达 +0.5000）！
