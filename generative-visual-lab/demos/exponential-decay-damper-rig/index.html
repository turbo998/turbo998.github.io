Damp cameras with α = 1 − exp(−λ·Δt). Stop lerp(x, target, λ·Δt) drifting across FPS or exploding on hitches.

为什么在几乎所有游戏和 3D Web 应用里，程序员最爱写的相机平滑跟随代码 `x = lerp(x, target, lambda * dt)`（即 `x += (target − x) * lambda * dt`）是一段**彻底违反微积分半群定律的错误代码**？因为把一个总时长 `T = 0.25 s`（目标位置 `target = 10.0 m`，衰减率 `λ = 8.0 s⁻¹`）的时间窗口切成 `N` 帧（每帧 `Δt = T / N`）连续迭代 `N` 次后，朴素线性 `λ·Δt` 权重留下的剩余误差是 `(1 − λT/N)^N`——这个值**随着帧率 `N` 的变化而剧烈漂移**！更致命的是：一旦遇到着色器编译或垃圾回收造成的单帧卡顿（第 0 站 `N = 1, Δt = 0.25 s`），乘积 `λ·Δt = 8.0 × 0.25 = 2.0 > 1.0`，朴素 `lerp` 会直接把原本停在 `0 m`、正往 `10.0 m` 平滑靠近的相机**瞬间弹射过冲到 `x = 20.0000 m`（比真实轨迹 `8.6466 m` 飞出去 `+11.3534 m`）**！即使在正常帧率波动（`N = 2..17`）下，不同刷新率显示器的相机跟手速度也完全不同（污染全部 `17/17` 个帧率站点）！采用 Rory Driscoll（2016）与 Freya Holmér（2024）推广的精确指数衰减阻尼核 `α = 1 − exp(−λ·Δt)`，利用指数半群恒等式 `(e^(−λT/N))^N ≡ e^(−λT)`，无论 `T = 0.25 s` 被拆成 1 次大卡顿还是 17 次高频微步，相机到达的位置永远分毫不差地锁死在 `x(0.25s) = 10·(1 − e⁻²) = 8.6466 m`！An original 17-station 3D chronometer damper bench compares exact exponential decay against naive frame-dependent linear-dt lerp.

This bench evaluates deterministic Rory Driscoll (2016) & Freya Holmér (2024) frame-rate independent exponential decay damping (α = 1 − exp(−λ·Δt)) versus naive frame-dependent linear-dt lerp (α = λ·Δt) and 64-substep 4th-order Runge-Kutta (RK4) ODE integration across 17 frame-rate subdivision stations (N ∈ [1, 17] steps over T = 0.25 s). It does not execute neural video stabilization networks.
